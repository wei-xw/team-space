我需要重构用户权限模块。当前使用的是简单的 role 字段（admin/editor/viewer），需要改为 RBAC 模型。

业务约束：
1. 需要支持 OA、CRM、招聘三个系统的权限隔离
2. 角色可以自定义，但默认提供 5 个预设角色
3. 权限粒度到菜单+按钮级别
4. 需要考虑向后兼容，现有用户数据需要迁移

请先帮我设计数据模型，再给出迁移方案。
AI
好的，根据你的业务约束，我来设计 RBAC 数据模型。

核心设计思路：
采用 RBAC + 系统域隔离的混合模型，通过 system_domain 字段实现 OA/CRM/招聘的权限隔离。 

-- 角色表
CREATE TABLE roles (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  system_domain VARCHAR(20) NOT NULL,  -- 'oa' | 'crm' | 'recruit'
  description TEXT,
  is_preset BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 权限表
CREATE TABLE permissions (
  id SERIAL PRIMARY KEY,
  resource VARCHAR(100) NOT NULL,  -- e.g. 'menu:approval'
  action VARCHAR(20) NOT NULL,     -- 'view' | 'create' | 'edit' | 'delete'
  system_domain VARCHAR(20) NOT NULL
);

-- 角色-权限关联
CREATE TABLE role_permissions (
  role_id INT REFERENCES roles(id),
  permission_id INT REFERENCES permissions(id),
  PRIMARY KEY (role_id, permission_id)
);
5 个预设角色：
1. 超级管理员（跨系统）
2. 系统管理员（单系统）
3. 部门主管（部门范围）
4. 普通员工（个人范围）
5. 访客（只读）
